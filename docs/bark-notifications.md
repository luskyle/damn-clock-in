# Bark 推送到 iPhone

v0.6.1 本地候选版本新增 **运行设置 → Bark 推送到 iPhone**。
只需填写 Bark Key。邮件通知方式已移除，不再提供邮箱或 SMTP 设置。

## 配置与测试

1. 在 iPhone 的 App Store 安装 **Bark**，打开并允许通知。
2. 在安卓助手的 Bark 设置中只填写 **Key**，无需填写服务器地址。
   如果 Bark 首页显示 `https://api.day.app/你的Key`，只取其中的 `你的Key`，
   不要包含网址、斜杠、示例消息或查询参数。应用内置官方 HTTPS 服务器 `https://api.day.app`。
3. 点击“保存并发送 Bark 测试通知”，在 iPhone 确认收到。该按钮不打开 BOE，也不执行打卡。
4. 可点击“刷新 Bark 发送状态 / 重试”。Key 不会回显；
   再次打开设置时留空保存会保留原配置。

旧版已保存的地址和待发通知保持原目标不变；重新填写 Key 后，新消息使用官方服务器。
设置页面不再提供自建服务器地址输入。

无需修改打卡计划。真实手动打卡、定时打卡和权限、唤醒等前置失败复用同一结果出口：

| 推送状态 | 含义 |
| --- | --- |
| 打卡成功（已核验） | 已识别本次新增记录或本次成功反馈，最终考勤以 BOE 为准 |
| 打卡结果待核验 | 已尝试点击，但没有可靠成功证据，不能仅凭提醒重复提交 |
| 打卡未完成 | 没有尝试点击，例如登录失效、其他设备登录后被挤下线、权限或唤醒失败 |

每轮结果只入队一次，不为每次自动点击重试分别推送。页面测试、预检和正常休息日不推送。
助手不能绕过 BOE 登录，也不会为了测试通知而提交真实考勤。

## 隐私与网络

- Key 是推送密钥，不要发到聊天、截图或仓库。配置及待发目标均以 Android Keystore
  AES-GCM 加密保存在本机，不参与云备份；设置界面禁止截屏，密钥不写日志。
- 仅发送时段、结果、时间及简要原因，不发送 BOE 账号、凭据、页面、截图或位置。
  Bark 官方服务器和苹果 APNs 会处理中转内容。
  本实现未提供额外的端到端内容加密，不应把推送正文视为只有设备可见。
- 仅接受 HTTPS，检查正常系统证书，不绕过证书验证，不跟随重定向。
  使用官方 `POST /push` JSON API，密钥放在请求体，而不是请求 URL；
  仅在 HTTP 成功且 JSON `code` 为数值 `200` 时记录服务器已接受。
- 官方接口：[Bark 使用说明](https://bark.day.app/tutorial.md)、
  [Bark 服务端](https://github.com/Finb/bark-server)。

## 后台队列与边界

- Bark 使用持久化队列和系统任务。发送在线程执行，不阻塞打卡收尾和退出息屏。
- 断网或发送失败时保留内容，系统按指数退避重试；每批最多五条，每个渠道最多 100 条。
  满时明确报告新消息未入队，不静默丢弃旧消息。系统网络策略可能延后任务。
- 每条待发消息固定使用入队时的加密目标。更换 Key 不会把旧消息转给新 Key；
  如旧密钥已失效，可先关闭并清除旧配置及队列，再保存新 Key。
- “已加入待发队列”不是成功；“Bark 服务已接受”也不等于 iPhone 已展示通知。
  请检查 iPhone 网络、Bark 通知权限、专注模式等，并通过测试通知确认。
  服务器接受后断线或进程终止可能造成重复通知，不能保证严格一次投递。
- “关闭 Bark 并删除配置及待发推送”不会改变打卡计划；
  已经交给服务器的推送不能撤回。
- 关机、强行停止、计划根本未触发或结果入队前进程终止时，无法承诺提醒。
  不要把“没有收到推送”理解为打卡成功。

## 验证

单元测试覆盖只填 Key 时使用官方服务器、拒绝网址和无效 Key、旧版 HTTPS 地址兼容、
JSON 请求体、密钥不出现在请求 URL、UTF-8、
禁止重定向、HTTP 错误、业务错误、异常/超长响应和网络异常。
独立模拟器测试覆盖 Keystore 密文、旧目标快照、安全设置界面及失败保留队列，
同时验证邮件移除升级会取消旧任务、清除旧邮件配置和发件密钥，并保留 Bark 与打卡计划。
v0.7.1 同样覆盖微信 ClawBot 移除：删除旧任务、本机绑定和密钥，保留 Bark 的配置、待发队列及任务。
测试使用虚构密钥；真实 Bark / APNs 接收仍需在用户填写 Key 后由 iPhone 确认。
