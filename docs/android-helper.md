## 范围和安全边界

这是一个独立的 Kotlin Android App，**上下班计划及手动真实打卡固定为定位请求**。
首次计划默认关闭；用户确认开启计划或手动打卡后才发起真实请求。
“立即测试”和独立预检仍只用于测试，不提交。
没有额外确认弹窗的自动点击实现，没有网络接口调用，
不修改 BOE APK、不收集账号密码、不使用定位伪造或绕过人脸验证。
无障碍服务只有两个允许的导航目标：

1. `com.mobile.boe:id/tab_apps`（工作台）。
2. `com.mobile.boe:id/name_tv` 且文字严格为 `考勤打卡`（应用入口）。

导航只对这两个匹配控件或其最多三层可点击父容器执行节点点击，不使用导航坐标或手势。
若已处于 BOE 小程序，可执行一次系统返回，尝试回到工作台。
仅导航模式检测到“蓝牙打卡”“定位打卡”或“打卡记录”即停止。
真实打卡模式还要求标题“考勤打卡”和“打卡记录”均可见、
“定位打卡”按钮唯一、可见、启用且自身可点击。
首次使用节点点击；重试可使用实时识别到的唯一定位按钮中心轻触，
按钮边界必须完整处于当前活动窗口内，不使用固定坐标、不查找打卡按钮父容器、不猜测点击。
导航控件仍只使用原白名单节点点击。没有通用任意坐标或手势控制入口。
遇到账号锁定、登录页、权限弹窗、入口不唯一或运行中锁屏均停止；
仅导航最多 45 秒，真实定位含重试最多 60 秒且不得超过计划截止时间。

如果小程序无法向无障碍暴露文字，只记录“入口已打开，需要人工确认”，
**不会将它记为页面验证成功**。不存储页面文字、截图或考勤记录；最多保留 80 条
本地执行状态日志。App 不申请网络、定位、蓝牙、悬浮窗、设备管理员或 root 权限。
日志和调度状态不参与 Android 云备份或设备迁移。

## 真实打卡模式（v0.5.0）

### 开启和执行

1. 无需选择方式或开启独立提交开关。确认开启上班或下班计划，即按真实定位打卡运行。
   新安装计划默认关闭。升级时移除旧 `attendanceMode` 设置：
   原来已明确选择定位的计划保留；原非定位计划关闭并清除下一次时间，避免旧测试计划静默变成真实提交。
   时间窗口、当天已尝试标记、点击预算和既有结果均保留；迁移只执行一次并记录原因。
2. 手动执行时点击“立即打卡 · 需再次确认”，选择上班或下班，再次确认真实打卡。
   v0.5.1 起不限制当天手动发起次数，已有成功、待核验或此前重试用尽均不拦截新请求。
3. 定时执行时，重新开启对应计划，确认时间、方式及会产生真实记录的说明。
   后续到期不会再逐次弹窗询问；使用原有工作日、亮屏和安全锁屏规则。
4. 定位和相关权限由 BOE 按真实设备条件正常处理。
   助手不申请这些传感器权限，不伪造结果，也不绕过认证。
5. 每次点击后等待十秒核验。尚未核验成功时可继续，第二次后允许返回重进一次再试；
   每轮最多自动点击三次，整个真实定位流程最多 60 秒且不超过计划截止时间。
   返回后须通过正常工作台入口重新进入，不对尚未退出的旧页面立刻点击。

首页“立即测试”和“两分钟后息屏测试”始终只导航，不提交、不在到达页面后自动息屏。
“打卡预检”只选择上下班，不再选择方式；仅检查页面和定位按钮，
不关闭已有计划、不占用真实打卡次数，也不自动息屏。

### 每轮请求与结果核验

- 每轮首次点击前同步保存该时段最新请求的日期、首次请求时间、独立点击数和“结果待核验”。
  自动重试在同一会话内有界执行，不重新开启一份无限次数的任务。
- v0.5.1 不把旧请求日期、成功标记或耗尽的点击数作为新手动请求的拦截条件。
  每次明确确认都是新一轮，点击前更新最近请求的计数、核验起点和结果；旧请求不自动续跑。
  移除“继续待核验”入口，失败或中断后可通过“立即打卡”再次确认新请求。
  同一轮执行或收尾期间不并发创建另一轮，避免相互干扰。
- 定时计划仍由调度器的当天已尝试标记保证每个计划每天一个自动会话；
  手动请求不修改该标记，也不关闭或重新随机已有计划。手动请求可重复，不能保证服务端幂等。
- 请求前记录本次页面中已有文本；请求后只将**新增**且方式匹配的记录作为核验候选。
  当前已观察的格式是 `yyyy-MM-dd HH:mm:ss定位打卡`。
  时间须落在本次请求前五秒至当前时间后五秒的容差范围；旧记录、错误方式、
  非法日期、无关或超前记录不作为成功证据。
- 若只出现新的精确“打卡成功”提示，日志仅写“页面显示打卡成功”，仍以 BOE 最终记录为准。
- 成功标志优先于重试判断；无明确反馈先等待十秒再有限重试。
  额外认证、额外确认、预算耗尽、超时或页面不可识别时停止，并提示“结果待核验”。
  **点击已尝试后不会再错误地提示“未提交”。重复请求可能产生多条真实记录，不能保证服务端幂等。**
- 最近一次请求日期及摘要显示在对应时段卡片，便于进程重启后看到待核验状态；
  不持久化 BOE 页面内容、位置、截图或整条考勤记录。

### 成功后退出 BOE 并自动锁屏息屏

只有真实定位请求已经尝试点击、并被当前会话核验为成功，才执行收尾：

1. 先持久化成功摘要，停止点击和延迟检查，释放唤醒会话与 CPU 唤醒锁。
2. 发送结果通知，由无障碍服务调用 `GLOBAL_ACTION_HOME` 返回系统桌面；
   最多等待两秒检查 BOE 是否已离开前台，再调用 `GLOBAL_ACTION_LOCK_SCREEN`。
   退出期间拒绝新任务，避免延迟锁屏中断下一次任务。
3. 返回接受后记录“已请求”，一秒后检查屏幕是否仍可交互；未息屏时明确提醒人工确认。
   系统拒绝动作时也明确通知，不把请求成功直接当作屏幕已经关闭。
   返回桌面失败或未确认退出会通知，但仍尝试息屏，不无限停留在考勤页面。

“退出 BOE”指退出前台回到桌面，不是强行停止、清空数据或移除最近任务，不影响登录。
这是系统桌面与锁屏动作，会同时锁屏和息屏，不需要设备管理员或 root。
如果手机有安全锁，下次运行仍须按系统要求认证，不会为了下次唤醒而取消安全锁。
仅导航、预检、失败、超时、待核验以及重复调用停止函数均不会触发成功息屏。
重开首页或查看过去成功记录也不会再次锁屏。

### 本轮验收边界

用户明确要求后，在真机 BOE 正常页面点击一次定位打卡，
观察到一条此前不存在、对应本次请求时间的定位打卡记录，无额外确认弹窗。
这次请求通过调试 UI 操作执行，**不是新版助手自动提交链路的端到端验收**。
同签名安装 v0.5.0 后，新版定位预检在真机通过，没有再次点击打卡。
安装前后用户已有计划开关、时间窗口、下一次时间和当天防重复状态比对一致；
原下班计划保留为仅导航，没有擅自切成自动提交。

后续按用户要求完整执行新版真实定位流程：第一次节点点击未出现可验证新增记录，

助手继续剩余预算，第二次轻触后 BOE 新增定位记录，返回重进刷新后核验成功即停。

## 构建和安装

在仓库根目录执行：

```bash
bash scripts/build-android.sh
```

默认使用外置 android-lab 中现有的 Java 17、Gradle 8.9、SDK 34、Build Tools 34.0.0。
Gradle 使用离线模式；缺少依赖会明确失败，不自动下载。可通过 `ANDROID_LAB_ROOT`、
`JAVA_HOME`、`ANDROID_SDK_ROOT`、`GRADLE_BIN` 指向本机对应工具。
Android Studio 也可直接打开仓库目录（已有完整 Gradle 工程）。

输出 `app/build/outputs/apk/debug/app-debug.apk`，这是本地测试签名构建，不是商店发布包。
更新时使用同一开发签名；切换电脑导致签名变化时，不能直接覆盖旧 APK。
发布版签名与密钥管理尚未实现，不要将私有签名密钥提交到仓库。

模拟器：

```bash
bash scripts/android.sh helper-install
bash scripts/android.sh helper-open
```

真机先安装 BOE 移动门户、手动登录，之后通过文件传输安装助手 APK。
也可以用 USB 调试（明确选定真机，不要照抄模拟器序列号）：

```bash
ADB=/media/luskyle/DATA/android-lab/voice/tools/android-sdk/platform-tools/adb
"$ADB" devices -l
SERIAL=你的真机序列号
"$ADB" -s "$SERIAL" install -r app/build/outputs/apk/debug/app-debug.apk
```

安装配置后断开 USB，助手的定时和导航不依赖 adb、主机或模拟器。
支持 Android 10+；已在 Google APIs Android 15 模拟器及一加 Android 13 真机测试。
**不能据此宣称已经解决所有厂商后台限制**。

## 首次授权

1. 打开“永不迟到”，阅读仅导航的说明。
2. 在首页“运行设置”进入系统无障碍设置，手动启用“永不迟到 · 考勤辅助（需确认开启）”。Android 的授权能力
   比本 App 的使用范围宽，请仅安装你信任的本项目构建；可随时在系统设置关闭。
   如果系统提示受限设置，按本机正常的 App 安全设置流程确认来源，不使用 adb 强行授权。
3. 允许通知；Android 13+ 需运行时授权。
4. 若要定时，允许“闹钟和提醒”；Android 12+ 使用 `SCHEDULE_EXACT_ALARM` 特殊权限，
   不申请只适用于特定用途的 `USE_EXACT_ALARM`。
5. 在系统电池设置中允许该 App 后台运行；厂商自启动、后台保护等设置需按实际手机操作。
   面板的电池设置入口不能代替所有厂商专用配置。
6. BOE 登录、附近设备、定位、Wi-Fi、人脸等仍由你在原 App 正常处理。助手不代你授权。
7. 先保持屏幕解锁，在“运行设置”点击“先检查锁屏显示权限（不导航）”。
   如果厂商弹出“需要在锁屏上显示”，请在系统弹窗中允许，再点“完成，返回助手”。
   一加 Android 13 实测会额外询问这项授权；未提前完成时，后台亮屏页面会被系统挡住。
   这个入口只是展示授权检查页，不打开 BOE，也不代表息屏测试已经成功。

“立即测试”不要求精确闹钟权限；“每日测试”必须通过通知、精确闹钟、
无障碍连接及 BOE 安装状态检查。首次默认关闭定时。

## 上下班时间段与滚轮设置

首页分别显示“上班打卡”和“下班打卡”卡片，卡片名称表示计划用途，
**不表示已经实现或启用提交打卡**。

- 上班默认 `07:50–08:10`；下班默认 `17:30–17:32`，仅作为可编辑的初始值。
- 点击卡片的“设置时间段”，在并排的“开始 / 结束”滚轮中上下滑动小时、分钟。
  使用 24 小时制、整分钟精度，可循环滚动，不弹出数字键盘。
- 小时、分钟各自独立滚动；分钟跨过 `59 / 00` 不会自动改变小时。
- 开始必须早于结束，至少相差一分钟。暂不支持跨午夜。
- 两个时间段不允许重叠或共用端点，避免同时导航；无效设置留在编辑器显示错误，
  不覆盖原配置。
- “取消”不修改配置。保存修改仅关闭被修改的计划、取消其闹钟并清除旧随机时间；
  另一计划不受影响。需要重新开启并确认该计划；当天已尝试标记保留，防止改时间后重复执行。
- 每张卡有独立开关和下次随机时间。“停止测试并关闭全部计划”会同时取消两个计划。
- 新建或修改后重新开启计划时，如果当天是工作日、该时段当天尚未自动尝试且窗口未结束，
  当天生效；进入窗口后只在下一整秒到窗口结束之间均匀随机，不总是推到次日。
  已到窗口结束、当天已尝试或非工作日时排到后续工作日，不清除已有防重复标记。
  已保存的有效未来计划仍保持稳定，重开页面不会反复重抽。
- 权限、电池和保持面板亮屏选项在“运行设置”；本地日志在“执行记录”。
- 旧版单计划升级为上班计划，保留其启用状态、随机时间和已尝试日期；
  新增下班计划默认关闭，旧单计划闹钟被替换，不会重复保留。
- v0.3.0 升级时，原下班默认值 `17:30–18:00` 会一次性迁移为 `17:30–17:32`，
  关闭该下班计划并清除旧随机时间，等待重新确认；其他自定义窗口不改动，
  已尝试日期保留。上班既有计划恢复时也会重新检查工作日。

## 中国大陆工作日日历

自动计划仅在中国大陆工作日执行，两个时段统一使用该规则：

- 普通周一至周五执行、普通周六周日跳过。
- 法定节假日即使在周一至周五也跳过；周末调休补班日照常执行。
- 每次创建、恢复计划时选择下一个工作日，闹钟触发时再次检查当天日历。
- 不适用于单位另行安排的轮班、年假或地方特殊假期，也不推断个人出勤安排。
- “立即测试”属于主动测试，休息日也可以手动运行，但仍只导航、不提交。

当前内置 **2026 年**国务院官方安排：
[国务院办公厅关于2026年部分节假日安排的通知](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)，
国办发明电〔2025〕7号。数据保存在
[2026.properties](../app/src/main/resources/calendar/2026.properties)，运行时不请求第三方服务，
不需要网络权限，避免外部 API 故障或未公布年份的预测数据导致误执行。

2026 年调休补班：1 月 4 日、2 月 14 日、2 月 28 日、5 月 9 日、
9 月 20 日、10 月 10 日，其余按官方放假区间覆盖普通周历。

**未接入的年份不回退到“周一至周五”判断**：寻找下次工作日或执行当天校验时
发现缺失年份，会取消对应自动计划，记录错误并通知更新 App。
首页显示已支持年份。2027 年尚未在本版接入；跨年部署前必须更新日历。
若当日已有合法到期测试，但无法安排下一年计划，会暂停后续计划，
不影响当日合法窗口内的这一次测试。

新增年度数据需先核实国务院正式通知，新增同格式年度资源，在 `ChinaWorkdays.years`
登记，并补充放假、补班、跨年测试后重新构建安装；不采纳预测日历。

## 定时语义

- 仅中国大陆工作日执行，**跳过普通周末和法定假期，包含调休补班日**。
- 固定使用 `Asia/Shanghai`，不随手机显示时区改变。
- 每个计划分别在用户设置的开始整分钟到结束整分钟（含端点）之间随机选取整秒，
  并持久化；例如 `07:50–08:10` 有 1201 个候选整秒。
- 首次启用或修改后重新启用时，当天是工作日、尚未尝试且窗口仍有剩余则当天生效。
  起点前在整个窗口随机；窗口内在下一整秒到结束整分钟之间均匀随机。
  已到终点、非工作日或当天已尝试时，安排后续工作日，不在过去窗口补执行。
- 保留已有未来计划，重启或更新恢复时不重新随机选择。
- 设备在相应窗口内恢复且已有到期计划时，可以恢复该计划；超过该计划终点则跳过，
  不在窗口外执行。
- 在开始一次自动会话前记录当天已尝试；每个计划每天最多一个自动会话，
  上下班互不占用次数，失败不会重新注册当天自动会话。
  真实定位会话内可按三次持久化预算有限重试，与“再次注册当天自动会话”不同。
  手动真实定位不限当天次数，每轮单独计数，不占用自动计划当天会话；
  “立即测试”仅导航，不消耗真实点击数。
- 闹钟到期后立即安排下一个工作日。使用 `setExactAndAllowWhileIdle`，不是常驻轮询。
  接收开机完成、应用更新、校时、时区及精确闹钟授权事件恢复计划。
- 调度权限丢失或设置闹钟失败时明确记录错误；恢复路径会关闭失效计划，需重新启用。
- 超过执行窗口会中止运行；仅导航最多 45 秒，真实定位含重试最多 60 秒。
- 点击“停止测试并关闭全部计划”取消当前导航、唤醒、两个每日闹钟和单次测试，但保留原计划时间，
  以免在同一天反复开关时重新随机选择。

v0.4.0 起，定时会尝试亮屏：没有安全锁时请求系统解除普通锁屏并导航；
若有密码、指纹或人脸等安全锁屏，记录并通知你手动解锁、点击立即测试，
**不绕过认证，也不会在解锁后自动续跑**。
定时提醒不等于页面已打开，页面已打开也不等于已提交打卡。

### 两分钟后息屏测试

先完成上面的锁屏显示权限检查，再通过“运行设置 → 2 分钟后息屏测试（仅一次）”
安排独立的 `RTC_WAKEUP` 精确闹钟。
确认“安排并退出助手”后，助手会关闭首页并移除其最近任务，你可以直接熄屏；
无需手动重新打开助手，也不会通过首页跳转 BOE。这不是系统的“强行停止”。
它允许休息日测试，
不更改上下班时间、开关、随机时间或已尝试日期；重复安排只替换这一个测试。
闹钟消费后立即清除；迟到超过一分钟跳过，不补执行。
“停止测试并关闭全部计划”也会取消单次测试及正在进行的唤醒。

实现使用系统绑定无障碍服务的后台启动能力，打开独立、无最近任务记录的短暂亮屏页面，
通过 `setTurnScreenOn` / `setShowWhenLocked` 点亮屏幕。只在无安全锁时使用
`requestDismissKeyguard`，不改动锁屏配置。解除回调后还需确认设备实际亮屏且锁屏状态已更新，
最多等待八秒，不把“回调成功”误认为手机已可操作。CPU 部分唤醒锁有最多 65 秒超时，
完成、失败或停止时释放；亮屏页面会退出，不把 BOE 切回助手。
无障碍服务临时未连接时最多等待十秒重新绑定，不通过轮询无限保活。
若系统静默拦截后台页面，也会由超时检查记录失败，不声称已亮屏或已到达页面。
仅导航最多 45 秒、真实定位含重试最多 60 秒，均不超过计划窗口，迟到会缩短可执行时间。

### 一加划掉最近任务后无障碍被关闭

在一加 Android 13 上复现：返回桌面并重开连续三次正常，但手动划掉本应用的最近任务后，
系统清理器终止应用，同时系统的已启用无障碍服务列表变为空；不是仅连接暂时断开。

通过正常系统界面进入“应用详情 → 耗电管理”，开启：

- **允许完全后台行为**（可能增加耗电）。
- **允许应用自启动**。

“允许唤醒前台”保持开启；“允许应用关联启动”不需要开启。
这两个厂商开关与 Android 普通“电池优化豁免”不是同一项。
App 的“运行设置 → 自启动与后台保护（重要）”提供说明及本应用详情入口，
不会后台改写权限或宣称已经自动配置。
已经被关闭的无障碍服务仍需通过系统设置手动恢复一次。
开启上述两项后，原版本和 v0.4.4 各连续三次实际划掉最近任务，无障碍授权及连接均保留。
该结果仅代表本次一加实测，不代表所有品牌或系统升级后的永久保证。

运行设置现在分别显示“未授权或已被系统关闭”“已授权，暂未连接”“已连接”。
暂未连接不再被误报为从未授权；定时任务可等待最多十秒重新绑定。
真正被关闭时会明确提醒手动恢复，不尝试静默授权。

对照测试还确认：**即使开启上述保护，系统“强行停止”仍会清空该机的无障碍授权**，
随后正常打开应用、同签名覆盖升级也不会自动恢复，必须正常进入系统设置重新授权。
不要把“划掉任务已保留授权”理解为“强行停止后能自行复活”。
v0.4.4 已在真实未授权和已连接两种状态下检查界面提示，后台保护入口能打开本应用详情；
覆盖升级保留了厂商后台设置，关联启动仍关闭。
普通进程异常终止后的恢复、重启和长期休眠不在本轮已完成验证范围。

本版使用系统绑定的无障碍服务进行短时导航，不使用常驻前台服务或“保活黑科技”。
这不能消除厂商后台限制或 Android 后台启动限制：系统禁止唤起时记录失败，
你可以按通知打开助手继续手动测试。

推荐专用设备：

- 接电、稳定联网；电池老化或长时间充电发热需按设备说明处理。
- 自行决定是否配置为无安全锁屏；本 App 不更改锁屏策略。
- 可选择勾选“保持本测试面板亮屏”。该选项仅当本面板可见时生效，
  不阻止手动关屏，也不会在导航结束后把 BOE 强行切回助手；测试后可手动返回面板。
- 允许后台运行、自启动，检查 BOE 仍已登录；不要对助手强行停止。
- 若手机被系统强行停止、关机或首次启动后尚未解锁，不能保证执行。
  也没有实现 Device Owner/Kiosk 注册或远程通知通道。
- Android 休眠期间对精确闹钟仍有配额限制。设置过于接近或非常窄的时间段，
  可能因系统延迟而跳过，不能将“精确闹钟”理解为绝对准点保证。

普通日常手机建议使用“通知 → 用户解锁 → 立即测试”的半自动模式。
Device Owner 专用设备管理需要额外的设备准备和真机验收，不属于本版已交付功能，
不会擅自恢复出厂或接管设备。

### 重跑仪器测试

仅针对可重置的测试设备运行。先通过系统设置授予助手精确闹钟权限，并在助手中关闭全部计划及单次测试。
测试若发现生产计划、单次闹钟或唤醒会话仍启用，会拒绝执行，不会为了测试而擅自关闭你的计划。
Gradle 的 connected 测试流程可能卸载重装助手，清除其配置并重置授权；
不要在正在日常使用的设备上执行。测试后须检查并重新配置权限。

```bash
# 将 ANDROID_SERIAL 改为明确选定的测试设备
ANDROID_SERIAL=emulator-5554 bash scripts/build-android.sh :app:connectedDebugAndroidTest
```

界面测试本身会滑动滚轮、保存测试时间，结束后恢复测试进程开始时的窗口和计划时间；
这不能防止外层 Gradle 卸载流程清除 App 数据。
仪器测试不点击 BOE 的考勤按钮，也不会把计划留在开启状态。
直接安装测试 APK 并运行 instrumentation 也可能使系统暂时断开无障碍服务；
测试结束后必须检查“已连接”，必要时在系统设置重新开关此前已授权的服务。
