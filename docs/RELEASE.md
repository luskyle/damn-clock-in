# 永不迟到 v0.8.3 · 测试版交付

**我的打卡时间我做主。**

上下班计划固定为真实定位打卡，不设独立的自动定位开关；核验成功后退出 BOE 前台并锁屏息屏。
首次计划默认关闭；立即测试和预检仍不提交。
本说明用于本地交付及 GitHub 标签发布；线上状态以对应 Release 和 Actions 成功结果为准。
名称不构成不会迟到、可靠唤醒或考勤成功的保证。

## 本版内容

- 原打卡核验成功出口继续发送 Bark，新增“模拟打卡成功通知（不打卡）”复用同一结果通知链路，
  不打开 BOE、不写考勤记录或计划、不息屏；消息明确标为模拟，避免被当作真实成功。
  真机已通过正常按钮发送一条模拟成功推送，Bark 服务确认受理；
  iPhone 展示需本人确认，考勤、计划及 BOE/Bark 配置前后完全一致。
- 运行设置根据实际配置和授权状态着色：已完成绿色，未完成或待核验淡红色；
  保留文字状态，自启动与锁屏显示不以打开过页面代替实际核验，测试动作使用中性色。
  两项新增模拟器 UI 测试验证实际颜色、配置保存/删除后的状态变化及计划不变；
  真机已覆盖安装并确认显示，BOE/Bark 凭据及计划保持不变。
- 修复上次登录失败后，手动测试、预检和立即打卡也被暂停标记拦截的问题：
  用户主动发起新请求时，允许一次新的帐号密码填充及登录；
  后台和定时任务不自动解除暂停，同轮仍只提交一次登录。
- 新增可选 [BOE 帐号与自动重新登录](boe-auto-login.md)：帐号密码仅在本机加密保存，
  识别“此账号在其他地方登陆”后确认并填写已验证的 BOE 登录控件。
  用户须先明确同意登录隐私政策，每轮只提交一次；密码错误、额外认证或结果未确认时暂停。
  恢复成功后继续原打卡流程；已点击过打卡后失效则保留待核验，不自动重复提交。
  单独登录测试不打卡、不息屏；安卓重新登录可能挤下线 iPhone，不绕过 BOE 多设备规则。

  本机清理不代替微信侧解除授权，如曾绑定，请在微信 ClawBot 管理中另外解除。

  不需要发件邮箱；提供测试通知、加密存储、独立后台队列、失败保留及重试。

  升级会取消旧邮件任务，清除旧邮件配置、待发邮件和发件凭据，保留 Bark 配置和队列。

  每轮首次实际点击前保存新的请求起点和独立计数，旧记录不能作为本轮成功证据；

## 交付文件与签名边界

| 文件 | 用途 |
| --- | --- |
| `yongbu-chidao-0.8.3-test.apk` | 可安装的测试签名 APK，非生产签名 |
| `yongbu-chidao-0.8.3-unsigned.apk` | 未签名 release APK，不能直接安装，供自行生产签名 |
| `INSTALL.md` | 本说明 |
| `SHA256SUMS` | 上述文件的 SHA-256 校验值 |

CI 在隔离 runner 上生成临时 Android debug 密钥，不上传、不持久化签名私钥。
**不同 CI 运行的测试 APK 签名可能不同，也可能与本机安装版本不同，不能保证覆盖升级。**
遇到 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，不要直接卸载日常使用版本；
先记录时间设置、关闭计划，决定是否接受卸载导致配置和授权丢失，再重新安装。
本机保持同一开发密钥构建的版本可覆盖本机此前测试包；不要把它与 CI 签名混淆。
仓库不包含生产 keystore、密码或自动托管生产签名。需要稳定生产升级时，
由维护者离线保管并使用同一个私钥自行签名；切勿将密钥提交到仓库。

先下载到同一目录并运行 `sha256sum -c SHA256SUMS`。
测试设备安装：`adb -s <设备序列号> install -r yongbu-chidao-0.8.3-test.apk`。
不要对未签名 APK 直接执行安装。

## 安装后验收

1. 安装移动门户，由用户自行登录，或在助手运行设置配置 BOE 帐号密码并验证登录。
   打开“永不迟到”，确认首页标语及图标。
2. 允许运行设置中的通知、精确闹钟，手动开启
   **永不迟到 · 考勤辅助（需确认开启）** 无障碍服务。
3. 通过“自启动与后台保护（重要）”检查厂商设置。一加 / OPPO 在“应用详情 → 耗电管理”
   开启“允许完全后台行为”和“允许应用自启动”，可能增加耗电；无需为此开启关联启动。
   若无障碍已被系统关闭，仍需手动恢复一次。在解锁亮屏时先检查“锁屏显示权限”。
4. 检查上班 `07:50–08:10`、下班 `17:30–17:32`。首次安装计划默认关闭；
   升级保留时间及防重复标记，原已确认定位的计划保留；旧非定位计划关闭并提示重新确认，
   避免导航测试计划被静默改成真实提交。
5. 使用“立即测试”或独立的“两分钟后息屏测试”，确认只到考勤页且没有提交。
   **此交付及 CI 不会自动打开 BOE，也不会开启任何每日计划。**
   需要真实打卡时，另按[真实打卡模式](android-helper.md#真实打卡模式v050)确认计划或手动操作。
   v0.5.1 已完整真机验证同日再次手动提交、退出 BOE 前台与息屏；完整验收边界见上文。
6. 安全锁屏需手动解锁；强行停止、关机、长时间休眠和厂商限制无法保证运行。
   当前仅内置官方 2026 年工作日日历；未接入年份暂停，年度自动更新尚未实现。

CI 没有用户 BOE APK、登录会话或真机，因此不执行 BOE 导航、不冒充真机验收。
设备仪器测试需要另按[真机说明](android-helper.md)
在明确选定的测试设备执行。

## 维护者发布步骤

1. 更新 `app/build.gradle.kts` 的 `versionCode`、`versionName` 及本交付说明的版本。
2. 本机构建：
   `bash scripts/build-android.sh :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease :app:assembleDebugAndroidTest`
3. `bash scripts/package-release.sh`，然后 `cd dist && sha256sum -c SHA256SUMS`。
4. 提交并推送代码；审阅 main 分支 CI 后创建与版本一致的标签，
   例如 `git tag v0.6.0 && git push origin v0.6.0`。
5. 在 Actions 检查成功，再检查 Release 的四项资产及校验值。失败时不要宣称已发布。
   标签发布为测试预发布，不能当作生产商店版本。
