# 普通微信扫码绑定与打卡结果通知调研

调研日期：2026-11-02。目标为普通微信，不是企业微信；本文保留接入前的方案比较，
当时没有创建平台账号、扫描授权码或发送真实消息。
曾在 v0.7.0 试接 ClawBot，现已按用户要求在 v0.7.1 移除；
本文仅保留历史调研，不代表应用提供微信通知。公众号候选未接入，当前仅保留 Bark。

## 结论

“安卓展示二维码 → 用户用微信扫码 → 关注后接收专属打卡结果”的交互可以设计，
但要区分两种不同的产品：

1. **公众号通知**：关注服务商公众号，在普通微信内接收消息；
   不是真人好友机器人，但更接近“关注后无需每天主动聊天”的目标。
   优先验证 **pushplus 的微信公众号渠道**。
2. **微信 ClawBot / iLink**：确有扫码绑定的微信机器人接入路径，不是企业微信，
   也不能再笼统地说“微信没有机器人接口”。不过当前查到的两家服务商均明确列出
   **24 小时主动交互窗口和 10 条消息限制**，不适合承诺一次扫码后永久免操作通知。

不能把“可创建二维码”“API 返回受理成功”当作真实微信收信已验证。
本轮未取得服务商账号及真实收信结果，公众号渠道的账号资格、当前额度、通知展示方式和
无需再次交互的长期可达性，都必须先用实际账号验收。

## 已核实的候选方案

| 方案 | 普通微信接收 | 二维码与绑定 | 关键限制与判断 |
| --- | --- | --- | --- |
| pushplus 微信公众号渠道 `wechat` | 文档明确支持，与 `cp` 企业微信渠道不同 | 开放接口列出个人二维码；好友回调 `add_friend` 包含自定义 `qrCode` 和好友令牌；发送接口支持 `to` 定向发给好友 | 最接近目标，建议先做真实收信验证；实名认证、好友数量、额度和账号权限以平台当前策略为准 |
| pushplus 微信 ClawBot `clawbot` | 是，机器人会话 | 官方说明为扫码绑定，绑定后还需主动发送一条消息 | 文档列出每 10 条、每隔 24 小时需要主动对话；一个微信号只能绑定一个 ClawBot，不适合作为无需维护的唯一提醒渠道 |
| WxPusher + 微信 ClawBot | 是，需要单独绑定该渠道 | 有参数二维码、关注回调和扫码 UID 查询；当前文档要求在 WxPusher App 中完成 ClawBot 绑定 | 文档明确激活后 24 小时内最多 10 条，需回复激活；额外安装客户端，不是仅扫一次码即可完成全部步骤 |
| 自建公众号 | 可作为候选架构 | 带场景值二维码与用户订阅事件可用于关联设备 | 需要自己的主体、公众号接口权限和服务端；模板、通知场景及审核资格本轮未验证，不能预设可以任意推送 |
| 个人号非官方协议或网页自动化机器人 | 可能存在第三方实现 | 通常涉及个人号登录或好友绑定 | 不作为推荐路线：账号与协议稳定性、封禁及隐私风险，不应把个人微信登录凭据交给陌生机器人 |

### 为什么不能直接照搬旧版 WxPusher 教程

当前 WxPusher 官方文档明确写明：平台早期主要使用公众号，现主推独立全平台客户端，
微信 ClawBot 是补充渠道。旧 SDK README 和部分文档段落仍有“关注公众号即可收信”的描述。
因此，不能仅凭旧教程承诺现在只需关注其公众号就能长期收到微信消息。

### ClawBot 并不要求引入整套 AI

OpenClaw 当前文档确认，腾讯微信团队维护外部 `@tencent-weixin/openclaw-weixin` 插件，
支持二维码登录、单聊和出站消息。扫码是机器人绑定/授权流程，不等同于关注公众号。
这可以作为技术路线的依据，但不代表需要把完整 OpenClaw 或大模型服务放进本应用。
本轮没有安装或运行该插件，也未独立验证其绕过服务商之后的主动消息时效；
上表的窗口限制来自各服务商当前文档，不能假定更换 SDK 就能消除。

## 建议的最小验证顺序

1. **先验证 pushplus 公众号渠道，不先开发完整绑定功能。**
   使用维护者自己控制的平台账号，普通微信关注该服务号，用 `channel=wechat` 发一条
   不含账号、位置等信息的虚构测试结果，确认收到的确实是微信通知，而不是 App、
   企业微信或仅网页消息。
2. 验证超过 24/48 小时、没有再次聊天后是否仍能收取符合平台规则的通知，
   同时核实当前实名、额度和用户接入要求。不能以短时成功代替长期无人值守验收。
3. 确认个人二维码、自定义参数和好友回调的实际可用权限，再做安卓扫码绑定。
4. 若公众号渠道不符合需求，再决定是否接受 ClawBot 的定期主动激活；
   不接受则继续使用 Bark，不应把有窗口限制的微信渠道包装为永久可用。

## 若验证通过，安卓扫码绑定如何落地

推荐一个轻量服务端，不把公共平台的管理密钥硬编码到 APK：

```text
安卓请求新绑定
  → 服务端创建随机、短时、单次使用的绑定会话
  → 服务端取得带会话参数的个人二维码
  → 安卓展示二维码和有效期
  → 用户用普通微信扫码，按提示关注并确认
  → 平台好友回调携带会话参数和接收方标识
  → 服务端核验接收方及绑定状态，完成设备与微信接收方关联
  → 安卓收到“绑定成功”，提供测试、解绑和重绑

打卡结果
  → 安卓持久化队列
  → 带设备身份的服务端请求
  → 平台微信公众号渠道，指定该用户的接收方
  → 用户普通微信
```

这是一份基于已公开能力的设计，不是已实现或已通过平台验收的功能。

- 不使用公开群组主题承载每个人的考勤，避免把用户结果发给其他订阅者。
- 固定的公众号二维码只能用于关注，不能单独可靠地关联“哪台安卓归哪个用户”；
  需要独立会话、防过期、防重放和用户确认。
- 平台回调不能无条件信任：核实签名或结合服务端查询确认接收关系，再标记绑定成功。
  pushplus 的开放接口要求管理级密钥、安全 IP 和定期更新 AccessKey，适合服务端保管。
- APK 只持有可撤销的本设备凭证；平台管理密钥、其他用户的接收方标识不下发。
- 明确告知结果摘要将经自有服务端、第三方平台和微信处理；只发送时段、结果、时间、
  简要原因，不发送 BOE 凭据、截图、页面或位置。
- 提供解绑、停用和失败状态；API 接受不等于手机已收到，网络中断和进程被杀仍可能延迟。

## 一手来源与验证边界

- [pushplus 发送接口](https://www.pushplus.plus/doc/guide/api.html)：
  `wechat`/`clawbot`/`cp` 渠道区别、好友 `to`、自定义二维码参数和 `add_friend` 回调。
- [pushplus 开放接口](https://www.pushplus.plus/doc/guide/openApi.html)：
  个人二维码、好友管理、AccessKey、密钥及安全 IP 要求。
- [pushplus 微信 ClawBot 使用说明](https://www.pushplus.plus/doc/channel/clawbot.html)：
  扫码绑定、一次主动对话、10 条和 24 小时限制。
- [WxPusher 当前完整说明](https://wxpusher.zjiecode.com/docs/README.md)：
  2026-11-01 更新，客户端优先策略、ClawBot 绑定与窗口、参数二维码和 UID 查询。
  该平台还提供不依赖回调的扫码 UID 查询，但要求间隔不小于 10 秒并在退出后停止查询。
- [WxPusher 标准 API](https://wxpusher.zjiecode.com/docs/api-reference.html)：
  `appToken`/UID、异步受理不等于送达。
- [OpenClaw 微信接入文档](https://docs.openclaw.ai/channels/weixin)：
  腾讯维护的外部插件、二维码登录和单聊能力。

旧版微信公众平台模板消息、参数二维码文档链接本轮访问返回 404，
未据此宣称已核实当前自建公众号的权限或额度。收费和平台规则可能变化，
不承诺永久免费、永久可达或免审核。该公众号方案没有创建后端、内置共享密钥或发送真实消息；
后续 ClawBot 试接已移除，当前应用不提供扫码绑定或微信消息推送。
